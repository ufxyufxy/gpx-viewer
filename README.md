# GPX 轨迹查看器

按日期查看一堆 GPX / FIT 轨迹，电脑和手机都能用，不装任何 App。

分组看的是**轨迹里记录的实际时间**，不是文件名：一条轨迹记在哪一天，就归到哪一天。想看哪几天就显示哪几天。

现在有两套界面，随你挑：

- `gpx-viewer.html`：**经典版**，左侧日期列表 + 勾选框，简单直接
- `gpx-timeline.html`：**时间线版**（参考 Dawarich 重做），全屏地图 + 顶部时间范围 + 日历热力图 + 统计 + 图层，默认深色主题

两版共用同一套数据和同一份浏览器缓存，可以互相接着用；打包出来的数据格式也是通用的。

---

## 两种用法

### 一、现成的网页（不用 Python）

双击 `gpx-viewer.html`（经典版）或 `gpx-timeline.html`（时间线版），然后：

- 电脑：把 .gpx / .fit 拖进窗口，或者点「选文件…」「选文件夹…」
- 手机：点「选文件…」（能多选）或「选 ZIP…」

地图组件已经内联在这两个文件里（约 210 KB），**断网也能打开界面**，只有地图底图需要联网。
文件数量不设上限，几百个一起选也行。时间线版的用法见下面「时间线版」一章。

关于速度和 FIT 格式，见「导入速度与 FIT 支持」一章。

### 二、整个文件夹打包成一个文件（手机首选）

把文件夹里的 `.gpx` 和 `.fit` 一起打进一个 HTML：

```bash
python 生成查看器.py "D:/我的轨迹"
```

在 `D:/我的轨迹/` 下生成 `轨迹查看器.html`，轨迹数据已经内联进去：

- 双击就能开，不用再选文件
- 拷到手机用浏览器打开，直接就是列表 + 地图
- 只有地图瓦片需要联网

常用参数：

```bash
python 生成查看器.py "D:/我的轨迹" -o "D:/总览.html"     # 指定输出位置
python 生成查看器.py "D:/我的轨迹" -r                     # 连子文件夹一起收
python 生成查看器.py "D:/我的轨迹" --simplify 3           # 每 3 米抽一个点，文件更小
python 生成查看器.py "D:/我的轨迹" --range 2025-03-01:2025-03-31   # 只要这个月
python 生成查看器.py "D:/我的轨迹" -t gpx-timeline.html   # 用时间线版界面打包
```

不加 `-t` 时输出 `轨迹查看器.html`（经典版）；加了 `-t gpx-timeline.html` 输出 `轨迹时间线.html`（时间线版）。两份都是数据内联、拷到手机就能开。

## 经典版的界面怎么用

- 左侧（手机上是底部抽屉）按日期倒序列出，最近的在最上面
- 勾选框：控制这一天显不显示；点整行也能切换；「全选」「清空选择」一键搞定
- 「定位」：地图跳到这一天的范围
- 「最近7天 / 最近30天 / 本月」：一键只留这段时间
- 「清空轨迹」：清掉页面里已导入的轨迹（不动手机/电脑上的文件）
- 「导出快照」：把当前轨迹存成一份自包含 HTML，刷新 / 换浏览器都不会丢
- 搜索框：输 `2025-03` 或 `0315` 筛选
- 右上角切底图：高德 / 卫星 / 街道(原始)
- 手机：点底部标题栏或小横条收起/展开列表

日期多的时候列表先渲染 60 天，往下滑自动接着加载。

## 时间线版（参考 Dawarich）

`gpx-timeline.html` 是照着 Dawarich / Google Timeline 的交互重做的一版：地图是主角，顶部选时间范围，左边一条图标栏按需展开面板，默认深色主题。

### 选时间范围

- 顶部两个日期框是起止日期；填成同一天就是看单日，两个都清空就是全部
- 快捷按钮：单日 / 最近7天 / 最近30天 / 本月 / 全部
- 日期框两边的 ‹ › 把整个范围平移一天，键盘 ← → 一样
- 时间线面板里点某一天 = 只看那天；勾选框可以单独加减某天，方便看不连续的几天
- 日历里点一天 = 单日，按住 Shift 再点另一天 = 选一整段，点「只看本月」= 整月
- 首次导入自动定位到最近 7 天；如果那 7 天里几乎没数据（比如打开的是很久以前打包的页面），会自动扩到最近 7 个有轨迹的日子，不会一进来只看到孤零零一天

选好范围后，地图、时间线、统计、日历会一起更新，右下角图例给出当前显示的天数和总里程。

### 五个面板

左边竖排图标（手机上是底部横排），点同一个图标再收起；键盘快捷键 T / C / S / L / I，Esc 关闭。

- **时间线 (T)**：按日期倒序的卡片，每天显示里程、轨迹条数、点数、起止时间；点卡片跳到那一天并缩放地图
- **日历 (C)**：月视图热力图，颜色越深那天走得越多；可翻月、回今天、只看本月；打开时会自动跳到最近有数据的月份
- **统计 (S)**：天数 / 总里程 / 轨迹条数 / 点数四张卡，近 12 个月里程柱状图（点某个月直接跳过去），以及平均每天、走得最多的一天
- **图层 (L)**：轨迹线、轨迹点、热力图、起终点、按速度着色，底图切换，深色/浅色主题与暗色底图
- **导入 (I)**：选文件 / 选 ZIP / 选文件夹（电脑），已导入多少个文件、上次选到哪个文件，以及清空按钮

### 图层与底图

- **热力图**：页面自己用 canvas 画的点密度图，不引第三方库、不联网；最多抽 12000 个点，缩放和平移后会重绘
- **按速度着色**：简化版，按整条轨迹的平均速度（里程 ÷ 起止时间）上绿（< 6 km/h）/ 黄 / 红（> 25 km/h）。不是 Dawarich 那种逐段测速，GPX 里没速度时也不猜
- **暗色底图**：把高德瓦片做反色处理，卫星图不反色；卫星 / 街道(原始) 照旧
- 高德、腾讯底图自动做 WGS84 → GCJ-02 纠偏；「街道(原始)」是 WGS84，不纠偏，适合境外轨迹。切底图时会清掉旧的投影缓存

手机上默认不展开面板，地图全屏；点底部图标才拉出抽屉，抽屉高度 52vh，再点一次收起。

### 打包成时间线版

```bash
python 生成查看器.py "D:/我的轨迹" -t gpx-timeline.html
```

在 `D:/我的轨迹/` 下生成 `轨迹时间线.html`，轨迹数据已经内联，拷到手机直接就是地图 + 时间线，不用再选文件。

### 和经典版比

| | 经典版 | 时间线版 |
|---|---|---|
| 主界面 | 左侧日期列表常驻 | 全屏地图，面板按需打开 |
| 选日期 | 勾选框 | 顶部起止日期 / 日历 / 快捷按钮 |
| 主题 | 浅色 | 深色（可切浅色） |
| 额外功能 | — | 日历热力图、月度统计、图层开关、热力图、速度着色 |
| 适合 | 就想快速勾几天看 | 想按时间浏览、看统计、换着花样看地图 |

底层是同一套：GPX 解析、跨零点拆段、GCJ-02 纠偏、ZIP 解压、每次点按钮换新的文件输入框、分批追加去重、浏览器本地缓存，两边都有。Dawarich 里的地点识别、行程（Trips）、家人共享、照片图层、Fog of War、3D 地球这些需要服务端或额外数据源的功能没有搬，这个页面始终是纯本地单文件。

## 导入速度与 FIT 支持

### 为什么以前慢，现在快在哪

之前每个 GPX 都交给 `DOMParser` 建整棵 XML 树，再对每个 `<trkpt>` 做一次子树查询找 `<time>`；文件一多，光解析就要等很久。而且文件是一个个顺序读的，进度每两个文件写一次 DOM，主线程一直被占着。

现在换了一套解析内核（`src/core.js`，构建时内联进两个 HTML）：

- GPX 改成字符串扫描：按 `<trkseg>` 切段，用 `indexOf` 顺序取 lat / lon / `<time>`，不再建 DOM 树
- 时间统一换算成毫秒数字，本地日期按「天」缓存边界，点级只剩两次数值比较，不再每个点 `new Date`
- 文件读取改成每 16 个一批并发 `arrayBuffer()`，批间用 `MessageChannel` 让出主线程，进度能刷新
- 进度文字按 90 ms 节流，不再每两个文件写一次 DOM
- 每批结束会提示「用时 X.X 秒」，方便自己看效果

实测同样 60 个文件 / 3.6 万个轨迹点，纯解析从约 **440 ms 降到约 50 ms**（约 9 倍），产出的轨迹段数和点数完全一致；整批导入还叠加了并发读取和让出主线程，手机上不会卡着不动。非标准 GPX 如果快速路径认不出来，会自动退回原来的 `DOMParser` 解析，不会丢数据。

### FIT 文件

`.fit`（Garmin、Wahoo 等导出的二进制）现在和 `.gpx` 一样能选、能拖、能放进 zip。

- 直接读二进制：文件头 → 定义消息 → 数据消息，只取 `record`(20) 里的 `timestamp` / `position_lat` / `position_long`
- 支持压缩时间戳头、大端 / 小端、开发者字段、多个本地消息定义；CRC 不校验（不影响轨迹）
- Zepp / Amazfit 这类国产设备会把 `0x80` 标志并进 base type（`0x85`=sint32、`0x86`=uint32、`0x84`=uint16），解析时会自动剥掉高位。已用真实 Zepp 导出文件验证：4545 个点 / 30.8 km / 04:15–05:40，坐标正常
- 解析不出来时会给出诊断：读到多少条消息、多少个定义、`record` 多少条、其中多少条带经纬度，方便判断是纯心率文件还是 GPS 存在自定义字段里
- 经纬度从 semicircle 换算成度，时间戳按 FIT 纪元（1989-12-31 UTC）换算成本地时间
- 关机再开机这种长时间中断（> 30 分钟）或大跳（> 5 km）会自动切成新段，不会连出一条横跨全城的直线
- 后面和 GPX 完全一样：按点的时间跨零点拆天、算里程、GCJ-02 纠偏、进日历和统计
- 心率、踏频、功率、海拔这些字段忽略；没有经纬度的 FIT 会跳过并计入「没解析出轨迹」

打包脚本也认 `.fit`：`python 生成查看器.py "D:/我的轨迹"` 会把文件夹里的 `.gpx` 和 `.fit` 一起收进去，输出里会分别报个数。

## 刷新后数据丢失怎么办

有人把 HTML 放在局域网网盘上、本地打开导入数据，刷新后发现轨迹没了。原因不是解析出错，是**浏览器本地缓存没保住**：

- 浏览器给 `localStorage` 的配额通常只有几 MB，轨迹一多（现在超过约 3.2 MB 就不缓存）就存不下
- 从网盘、下载目录、浏览器临时目录打开的 `file://` 页面，有些浏览器（尤其手机自带浏览器）会禁用或每次清空本地存储
- 隐私 / 无痕模式、清理浏览数据也会让它消失

现在页面写缓存后会读回校验，存不住就在导入结束时明确提示「本地缓存没存住（刷新会丢），请点导出快照」，不再静默失败。

**彻底的办法是导出快照**：把当前轨迹固化成一份自包含 HTML。

- 经典版：工具栏「导出快照」
- 时间线版：导入面板「导出单文件 HTML」

导出的文件名类似 `轨迹快照_2026-11-14.html`，里面已经内联了地图组件和全部轨迹数据，和 `生成查看器.py` 打出来的文件是同一种。把它存回网盘或拷到手机，双击打开就是完整数据，**刷新、换浏览器、清缓存都不会丢**，也不用再选一次文件。

建议：页面是从网盘 / 临时目录打开的，或者一次导入了很多文件，导入完顺手点一下导出快照，之后就用这份新文件。

## 体积与效率

Leaflet 1.9.4 的 `vendor/leaflet.js`（147 KB）本来就是官方压缩版，没法再压；能省的是样式、脚本和轨迹数据。

- **构建时安全压缩**：只删注释、空行和行首行尾空白，不合并行、不改变量名，字符串和正则完全不动。`python build.py` 默认压缩，`python build.py --raw` 可以出未压缩版对照；源码始终保留在 `src/` 里便于阅读。
- **坐标打包**：`生成查看器.py` 和「导出快照」现在把 `[[30.274030,120.161860],...]` 写成 ×1e5 的整数差值（第一点是相对 0 的差值，也就是绝对值），精度约 1 米，对地图足够。旧格式的坐标数组仍由 `TRACK.decodeSeg` 兼容；浏览器缓存从 v2 升到 v3 差值格式，老缓存照样能读。
- **运行时**：日期配色、列表索引改成 Map 查找，不再每次 `findIndex` / `indexOf` 全表扫描。

实测字节数：

| 文件 | 优化前 | 现在 | 省 |
|---|---:|---:|---:|
| `gpx-viewer.html` | 222,362 | 214,019 | 8,343（3.8%） |
| `gpx-timeline.html` | 244,837 | 236,887 | 7,950（3.2%） |
| 5 个 GPX 打包的经典版 | 253,284 | 223,626 | 29,658（11.7%） |
| 5 个 GPX 打包的时间线版 | 275,759 | 246,494 | 29,265（10.6%） |
| 4545 点的 Zepp FIT 打包版 | 348,622 | 260,164 | 88,458（25.4%） |

只看数据部分（Zepp 那条 4545 点的轨迹）：94,607 → 23,281 字符（-75%），`JSON.parse` 平均 0.56 ms → 0.24 ms。轨迹越多省得越明显，打开也更快。

没做的：把 Leaflet 再压一遍、或改成运行时解压内联。官方包已经 minified，而 `DecompressionStream` 在不少手机浏览器上不可用，为了兼容没上。

## 按哪一天分组

默认按轨迹里的时间分组：取每个轨迹点自带的时间（GPX 里的 `<time>`），换算成本机时区后归到那一天。
时间线版固定用这个规则；经典版可以用「分组：轨迹时间」按钮切到按文件名分组。
所以文件名写错、或者一个文件里录了连续几天的行程，都不会乱：

- 文件名 `2025-01-05.gpx`，里面记录的时间其实是 3 月 7 日 → 归到 **2025-03-07**
- 一个文件横跨零点（比如 6 月 1 日 18:00 骑到 6 月 1 日 02:00）→ 自动拆成 **6-01** 和 **6-02** 两天，
  列表里会标 `(1/2 天)`、`(2/2 天)`；两段在零点处首尾相接，线不会断，里程也不会重复计算
- 没有 `<time>` 的文件 → 退回用文件名里的日期（`2025-03-01`、`20250301`、`2025年3月1日` 都认）
- 文件名也没有日期 → 用文件修改日期
- 时间明显是假的（比如没定位时写 1970-01-01）→ 当作没有时间处理

经典版顶上的「分组：轨迹时间」按钮点一下会切到「分组：文件名」，也就是老办法：按文件名里的日期归堆，
一个文件只占一天（跨天的几段合回一条）。两种方式随时切换，勾选状态会跟着文件保留。

同一天有多个文件时，自动归到同一天，一天里再按开始时间排。

## 为什么默认用高德底图

GPS 轨迹是 WGS84 坐标，高德、腾讯的地图是 GCJ-02（火星坐标），直接叠会偏几百米。
程序自动把轨迹点做了 WGS84 → GCJ-02 纠偏，所以默认底图下路网和轨迹是吻合的。

「街道(原始)」用的是 Esri 的 WGS84 底图，不做纠偏，适合轨迹在境外的时候。

## 手机上怎么多选（重点）

手机的文件选择器是系统给的，网页改不了它的规则，但可以选对了姿势，少点很多次：

1. **能一次选完就别分几次**——进到放 gpx 的那个文件夹后，长按第一个文件进入多选，
   再用系统的「全选」（安卓是右上角 ⋮ 或长按后出现的按钮）把整个文件夹选上，一次导入。
   页面已经不限数量，几百个文件一起选没问题，导入时顶部会显示「读取 37 / 812」的进度。
2. **要分批的话，中间不要一个一个勾**——长按第 1 个文件后，用另一只手指把列表滑到第 100 个，
   再点一下，系统会把中间这一整段都选上（滑动选择）。这比逐个点快得多。
3. **最稳妥的是 ZIP**——把放 gpx 的文件夹压成一个 zip：电脑上右键「发送到 → 压缩(zipped)文件夹」，
   手机上在文件管理器里长按文件夹选「压缩」。然后点页面上的「选 ZIP…」，一次全导进去，
   没有数量限制，也不用反复进选择器。解压是页面自己做的，不联网。

页面这边配合做了两件事：

- **每次都换一个新的选择框**：点「选文件…」时会重建底层那个文件输入框。
  有的手机浏览器把上一次的选择状态留在输入框上，第二次打开就只剩单选、只能一个一个点；
  换成新的之后，每次打开都是干净的多选。
- **记住上次选到哪**：经典版在标题下方，时间线版在「导入」面板里，
  显示「已导入 312 个文件（4 批）· 上次选到 2025-06-12.gpx」。
  文件名是按日期排的，看一眼就知道下一次从哪个文件接着勾。
- **重复选不会重复算**：再次选到已导入的文件只会覆盖同名那条，不会出现两遍。

电脑上用 Chrome / Edge 打开时「选文件夹…」是可用的，直接选整个目录，最省事。


## 还是打不开选择器

1. 用 Chrome 或 Edge 打开这个 html，别用微信/QQ 内置浏览器（它们对文件选择器限制多）
2. 文件先放到手机的「下载」目录，浏览器才容易看到
3. 实在不行就用「用法二」打包好再拷过去——那份不需要选文件

## 数据量

- 默认按 1.5 米抽稀，一天的骑行/跑步轨迹通常几十 KB
- 坐标用整数差值打包后，数据部分约为原来的 1/4（见「体积与效率」）
- 300 天、上百条轨迹，打包出来大概几 MB，浏览器能开
- 上千条的话建议加 `--simplify 5`，或者用 `--range` 分段生成

```
├── src/timeline.html      时间线版源码模板
├── src/core.js            GPX / FIT 快速解析内核（两个模板共用）
├── vendor/leaflet.*       地图组件（构建时内联）
├── _test/                 5 条演示数据
├── _test2/                120 天演示数据
├── _test3/                zip 导入的测试包
├── _test4/                跨零点 / 文件名与时间不一致的测试数据
├── _test5/                分批导入的测试页
├── _test6/                选择框重建 / 连续追加导入的测试页

```

改了 `src/` 下的模板或 `src/core.js` 之后跑一次 `python build.py` 才会生效；只改某一个模板可以用 `python build.py timeline` 或 `python build.py template`。
